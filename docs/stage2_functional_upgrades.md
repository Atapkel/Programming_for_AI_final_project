## 4. Горизонты и защита от утечек

Обозначим `t` как последний полностью наблюдаемый месяц. Условная дата выдачи прогноза — 15-е число следующего месяца. Горизонт `h` означает целевой месяц `t+h`, а не число полных месяцев после 15-го числа.

- Ridge и Gradient Boosting используют **direct** подход: отдельная модель для каждого `h`. Для FX обучающая цель — `100 × (FX[t+h] / FX[t] − 1)`; прогноз переводится обратно в KZT через наблюдённый `FX[t]`. Для инфляции цель — месячная инфляция непосредственно в `t+h`.
- Собственные лаги на якоре: 0, 1, 2, 11 месяцев; лаги внешних групп: 0, 1, 2; dummy-переменные известного календарного месяца цели. Лаг 0 означает уже завершённый месяц `t`, не значение в будущем целевом месяце.
- Для обучения доступны только якоря, чья целевая дата `anchor+h <= t`. StandardScaler обучается только на этих строках. Гиперпараметры ML фиксированы: Ridge alpha=1; GB 200 деревьев, depth=2, learning_rate=0.05, subsample=0.8, random_state=42.
- Неизвестные внешние значения не прогнозируются и не подставляются. Отсутствие обязательного текущего предиктора вызывает явную ошибку до публикации. Первичный набор FX использует собственные изменения и Brent; для инфляции — собственные лаги, FX и Brent. Признаки ставки и дополнительной инфляции для FX исследуются отдельно в абляциях.
- SARIMA/ARIMA и ETS строят модельные рекурсивные траектории; Naive повторяет последнее значение, Seasonal Naive повторяет последние 12 месяцев. FX в статистических моделях логарифмируется; обратное преобразование точки даёт условную медиану, не скорректированное среднее.
- ARIMA order выбирается по AIC только на первом обучающем отсечении каждого окна и далее фиксируется. Для инфляции выбран `(1,0,2)` при сезонной части `(1,0,1,12)` во всех окнах; для FX: full и rolling120 `(1,1,0)`, post2015 `(0,1,1)`.
- Full расширяется от начала ряда. Post2015 начинается с сентября 2015. Rolling120 ограничивает обучающие якоря и цели последними 120 месяцами, сохраняя десять годовых циклов. Для лагов можно использовать известные значения до начала окна; число полных ML-пар уменьшается с горизонтом.
- MASE — среднее `|ошибка| / scale[t]`, где scale[t] — средняя абсолютная разность на всей доступной истории до t: лаг 12 для инфляции, 1 для FX. Шкала общая для всех окон/признаков одного отсечения. Нулевая шкала даёт NaN; sMAPE при обеих нулевых величинах даёт 0. MASE не равен отношению ошибок к Naive на текущем тесте: для такого сравнения отдельно приведён baseline gain.

Каждый горизонт использует **36 одинаковых отсечений для всех моделей и окон**, но целевые периоды между горизонтами различаются:

| Цель | Отсечения t | h=1: целевые месяцы | h=3 | h=6 | h=12 |
|---|---|---|---|---|---|
| Инфляция | 2022-10 — 2025-09 | 2022-11 — 2025-10 | 2023-01 — 2025-12 | 2023-04 — 2026-03 | 2023-10 — 2026-09 |
| USD/KZT | 2022-11 — 2025-10 | 2022-12 — 2025-11 | 2023-02 — 2026-01 | 2023-05 — 2026-04 | 2023-11 — 2026-10 |

Отсечения двух целей различаются на месяц из-за различной доступности CPI и FX. Результаты h=1 нельзя выдавать за качество h=12; Stage 1 также использует другие проверочные даты.

Будущий расчёт инфляции: последнее наблюдение 2026-09, условный origin 2026-10-15, цели 2026-10 — 2027-09. Для FX: последнее наблюдение 2026-10, origin 2026-11-15, цели 2026-11 — 2027-10. Это происхождение расчёта по snapshot, а не заявление, что прогноз действительно был опубликован в указанную историческую дату. Линии между direct ML-точками не представляют совместное прогнозное распределение.

## 6. Эффект признаков и абляций

Абляции: `ar`, `ar_cross`, `ar_brent`, `ar_rate`, `all`, `without_cross`, `without_brent`, `without_rate`. `ar` включает собственные лаги и календарный месяц. `cross` означает инфляцию для FX и изменения FX для инфляции. Brent представлен изменениями цены, ставка — уровнем. Все варианты ограничены post2015 и одинаковыми complete-case якорями **полного** набора признаков; различия ошибок не объясняются разным количеством строк обучения.

| Цель / модель / h | AR | Все признаки | Более показательный вариант |
|---|---:|---:|---|
| Инфляция / Ridge / 12 | 0,227906 | 0,353970 | AR лучше полного набора; исключение ставки снижает MAE до 0,257338 |
| Инфляция / GB / 1 | 0,239522 | 0,213618 | Без ставки: 0,185969; только AR+Brent: 0,191044 |
| FX / GB / 1 | 7,989191 | 6,971953 | Полный набор снижает MAE относительно AR на 12,73% |
| FX / GB / 12 | 41,145926 | 48,717043 | AR+инфляция: 31,856537; добавление ставки не даёт устойчивого улучшения |

Для Ridge-инфляции на h=12 полный набор **увеличивает** MAE на 55,31% относительно AR. Для FX/GB на h=12 AR+инфляция даёт на 13,36% меньшую MAE, чем Naive, однако вариант выбран после просмотра абляций. Он не был автоматически перенесён в будущие прогнозы: нужна независимая проверка. Эффект внешних признаков зависит от горизонта, модели и окна; больше признаков не означает лучшее качество.

Explainability: Ridge показывает коэффициент на одно стандартное отклонение обучающего признака, GB — impurity importance. Сравниваются три окна и первое/последнее отсечение, плюс future fit. Отдельная permutation-проверка обучает фиксированную модель до последних 24 целевых месяцев, использует h=1, post2015 и все признаки. Пять перестановок блоков по три месяца применяются к группам лагов. Это не тот же эксперимент, что rolling-origin ranking; стандартное отклонение перестановок не является доверительным интервалом.

Например, для FX/GB на отдельном holdout перестановка собственных изменений увеличивает MAE в среднем на 0,937 KZT, Brent — на 0,509 KZT. Результаты зависят от корреляции признаков и синтетических границ блоков. Коэффициенты и importance не устанавливают причинность.

## 7. Качество интервалов

Только ARIMA/SARIMA предоставляет поддерживаемые **модельные 95% маргинальные prediction intervals**. Они не являются confidence intervals среднего, не откалиброваны на проверочных ошибках, не учитывают неопределённость оценённых параметров и пересмотров данных. Для FX границы преобразуются из логарифмического масштаба. Для ETS, ML и базовых моделей границы отсутствуют.

Во всех 24 группах наблюдаемое покрытие — **36/36 = 100%**, против номинальных 95%. Средняя ширина при полном окне:

| Горизонт | Инфляция, п.п. | FX, KZT |
|---|---:|---:|
| 1 | 1,849 | 48,295 |
| 3 | 2,427 | 109,505 |
| 6 | 2,577 | 171,348 |
| 12 | 2,644 | 255,676 |

Границы широкие относительно текущих ошибок; 100% покрытия на 36 наблюдениях не доказывает хорошую калибровку. Ошибки многомесячных прогнозов перекрываются, поэтому обычная независимая биномиальная проверка покрытия здесь не обоснована. Интерфейс показывает coverage gap, среднюю ширину, число доступных интервалов и proper interval score: ширина плюс штраф `2/0,05` за расстояние каждого промаха за границу. Модельные полосы не являются одновременным 95% конвертом всей траектории.

Новые тесты покрывают границы меток и признаков для обоих target и всех h, изменение будущих данных, прямые будущие ML-прогнозы на 12 горизонтов, отсутствие текущего предиктора, одинаковые строки абляций, окна, fallback без выдуманного интервала, coverage/width/interval score, пересчёт метрик, нулевые знаменатели, повреждение дат/истины/метрик/моделей/границ, устаревание snapshot, контрольные суммы и сохранение предыдущего набора при неуспехе.

Проверки интерфейса проходят все восемь страниц через оба launcher, переключают target/window/horizon, проверяют reference, пустой выбор моделей, отсутствие базы без её случайного создания и обязательный выбор World Bank. На время навигации функции обучения заменяются функциями, вызывающими ошибку при обращении.

Реальные локальные серверы обоих launcher дополнительно вернули HTTP 200 для `/` и `/_stcore/health`, после чего были остановлены. Исходный sandbox запрещал bind порта; проверка выполнена с разрешённым временным доступом только к 127.0.0.1. Это HTTP/AppTest-проверки, не визуальная проверка в реальном мобильном браузере.

GitHub Actions настроен на Python 3.12 и 3.14; удалённый CI не запускался, поскольку commit/push не выполнялись.

## 10. Оставшиеся ограничения

1. Final-vintage данные и предположение о публикации предыдущего месяца к 15-му. Реальные release calendars и архивные vintages не восстановлены; реального real-time backtest нет.
2. Только 36 зависимых отсечений на горизонт. Окна, модели и признаки сравниваются исследовательски; нет независимого финального test после выбора лучшего варианта и нет коррекции за множественные сравнения.
3. Три окна не охватывают все возможные режимы. ARIMA-порядки выбраны один раз на начальном origin; ML-параметры фиксированы, nested tuning не проводился.
4. Direct ML даёт отдельные точки по горизонтам, не совместное распределение. Суммировать/перемножать границы разных месяцев для годовой неопределённости нельзя. Будущие ML-прогнозы используют первичные группы, не победителей абляций.
5. Интервалы реализованы только для SARIMA; эмпирическая recalibration, интервалы ML/ETS и simultaneous path coverage не реализованы.
6. Correlation, mean-shift tests и importance не доказывают причинность. F-тесты не робастны к автокорреляции и гетероскедастичности.
7. Data Quality различает сохранённый аудит и текущую календарную полноту. После изменения raw/processed следует пересчитать соответствующие этапы; Stage 2 помечает несовпадение входного snapshot.
8. Функциональная адаптивность задана CSS и проверена AppTest; визуальное тестирование на разных физических устройствах не выполнено.
9. Тяжёлый расчёт выполняется офлайн отдельной командой, не в Streamlit. Все запланированные для этого этапа группы экспериментов рассчитаны; отложенных групп нет. Внешние данные не скачивались заново.

## 11. Точные команды запуска

Из корня репозитория, с уже существующим `.venv`:

```bash
.venv/bin/python -m streamlit run app.py
# Эквивалентный вход; запускать отдельно:
.venv/bin/python -m streamlit run app/main.py

# Пересчитать только Stage 2, сохранив Stage 1:
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MPLBACKEND=Agg \
  .venv/bin/python -m src.evaluation

# Консоль: 6 — исходный staged pipeline, 9 — Stage 2, 8 — dashboard
.venv/bin/python main.py

# Проверки:
.venv/bin/python -m pytest -q
.venv/bin/python -m pip check
```

Для новой среды:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

Данные и рассчитанные результаты находятся в репозитории; обычный запуск dashboard не требует сети. Если нужно полностью обновить расчёты: сначала пункт 6 консоли, затем 9. После успешной публикации кеш обновляется по SHA-256. Правила восстановления после `.update-in-progress` остаются описанными в [Stage 1 report](stage1_reliability.md); удалять этот marker без проверки backup нельзя.

## 12. Рекомендации для Stage 3

Stage 3 **не начат**. Следующие шаги для отдельного согласованного этапа: архивы vintages и release-aware as-of joins; заранее зафиксированный финальный test или nested rolling validation для выбора окна/признаков; робастное сравнение зависимых ошибок с учётом множественного выбора; отдельный calibration-период для интервалов и проверка покрытия по режимам; независимая проверка перспективных абляций перед их переносом в будущие прогнозы; визуальные тесты доступности и mobile layout. Эти рекомендации не являются утверждением о гарантированном повышении точности.
